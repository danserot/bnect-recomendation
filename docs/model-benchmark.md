# Модель и бенчмарк

Страница: `http://127.0.0.1:5174/#model`, вкладка **«Модель и тесты»**.

## Исполнение и хранение

По умолчанию: `Xenova/multilingual-e5-small`, ревизия `761b726`, 384 измерения.
Модель исполняется на CPU в процессе backend через Transformers.js и ONNX Runtime.
Веса Q8; mean pooling, L2-нормализация, `max_length: 512`, префиксы `query:` и
`passage:`. Модель загружается лениво и переиспользуется процессом.

На компьютере файлы находятся в `.cache/models/Xenova/multilingual-e5-small/761b726/`.
В Docker `.cache/models` подключён только для чтения в `/app/.cache/models`.
На странице показаны фактические пути, файлы, размеры, ревизия и среда backend.
Сетевая загрузка модели отключена. В браузере работает React-интерфейс.
При Docker-сборке `ONNXRUNTIME_NODE_INSTALL_CUDA=skip` отключает скачивание
неиспользуемых GPU-библиотек установщиком ONNX Runtime; CPU-бинарники входят в npm-пакет.
Рабочие векторы закупок хранятся отдельно от весов модели, в PostgreSQL/pgvector.

## Методика

Фиксированный авторский набор `procurement-synonyms-ru-v1` находится в
`backend/src/model/dataset.ts`: 12 запросов с синонимами, 8 перефразирований,
4 сокращения. У каждого запроса один ожидаемый ответ и один близкий отвлекающий
документ. Каждый запрос ранжирует **все 48 документов**. Все тексты придуманы
для теста; рабочие Excel-файлы и БД не читаются и не изменяются. Обучения нет.

- **Top-1**: доля запросов, для которых ожидаемый документ первый.
- **Top-3**: доля запросов с ожидаемым документом в первой тройке.
- **MRR**: среднее `1 / место ожидаемого документа`.

Ошибки не исключаются. Страница показывает ожидаемый ответ, место, сходство,
время и три фактических первых ответа. Есть фильтры по типу запроса и ошибкам.
Отчёт и полный тестовый набор скачиваются в JSON.

Время загрузки и прогрева учитывается отдельно. Если модель уже в памяти,
повторная проверка готовности не выдаётся за холодную загрузку. После прогрева
измеряется векторизация корпуса с текущим `EMBEDDING_BATCH_SIZE` и 24
последовательных запроса с **принудительным обходом кэша**. P50 и P95 используют
метод ближайшего ранга. Медиана 10 обращений к заполненному кэшу показана отдельно.

Время запроса включает токенизацию, ONNX и нормализацию. Косинусное ранжирование
измеряется отдельно. HTTP, SQL, региональные фильтры и правила рекомендаций не
входят в тест. Запросов/с = `1000 / среднее время` последовательного запроса;
это не тест параллельной нагрузки. Другие обращения к модели могут увеличить
время из-за общей очереди. Косинусное сходство не является вероятностью ответа.

Небольшой русскоязычный синтетический набор не оценивает качество на всех
закупках, других языках или независимом промышленном датасете.

## API и CLI

- `GET /api/model` — описание текущей модели и полный набор.
- `GET /api/model/benchmark` — состояние, этап, прогресс и последний отчёт.
- `POST /api/model/benchmark` с `{}` — начать задачу; ответ `202`.
  Повторный POST во время выполнения получает `409 BENCHMARK_RUNNING`.

Задача продолжается после закрытия вкладки. GET-запросы не запускают inference.
Отчёт атомарно сохраняется в `output/model-benchmark/latest.json`; в Docker —
`/app/output/model-benchmark/latest.json` на volume `bnect_reports`.
Совместимый отчёт восстанавливается после перезапуска backend. Отчёт другой
версии модели или набора игнорируется.

CLI использует те же метрики и набор:

```powershell
npm.cmd run benchmark:model
# Или в Docker:
docker compose exec backend node backend/dist/backend/src/benchmark.js
```

CLI работает отдельным процессом. Для сопоставимой скорости запускайте его
отдельно от бенчмарка на странице, без конкуренции за CPU.

Unit-проверки расчётов, обхода кэша, API, блокировки повторного запуска,
сохранения, восстановления и повторной попытки после ошибки находятся в
`backend/tests/model-benchmark.test.ts`. Контролируемые векторы этих тестов
проверяют логику; качество измеряется реальным ONNX-запуском.
