# Локальная обработка конфиденциальных данных

Исходные Excel-файлы, импортированные данные, SQL-агрегации и вычисление embeddings остаются на этом компьютере. В приложении нет внешних LLM/API для таблиц, облачного импорта, аналитических счётчиков или внешних шрифтов. Frontend обращается только к своему `/api`.

Приняты следующие меры:

- `.xlsx`, `.xls`, `.xlsm`, `.xlsb` и рабочие CSV из `data/` исключены из Git; пример `*.example.csv` разрешён.
- Локальные `.env`, кеш модели, логи, отчёты и браузерные артефакты также игнорируются.
- При запуске через Node.js backend допускает только loopback и локальный PostgreSQL. В режиме `RUNTIME_MODE=docker` разрешены `HOST=0.0.0.0` внутри контейнера и имя БД `db`; Compose публикует frontend, API и БД только на `127.0.0.1`. Vite также слушает `127.0.0.1`.
- Docker-образы не содержат Excel, `.env`, кеш модели и базу. `data/` и `.cache/models/` подключаются с компьютера только для чтения; PostgreSQL и отчёты импорта хранятся в отдельных постоянных Docker volumes.
- Vite запрещает прямую выдачу Excel/CSV, `.env`, `.git` и `.cache` через файловые URL.
- CSP ограничивает соединения браузера своим origin и локальным WebSocket для разработки.
- E5 вычисляется локально на CPU. `allowRemoteModels=false` и `local_files_only=true` запрещают сетевую загрузку; отсутствие кеша вызывает ошибку вместо внешнего обращения.
- Автоматическое журналирование URL запросов выключено, поэтому поисковые строки не записываются. Ошибки API не печатают содержимое запроса. Импорт печатает только счётчики, структуру и путь к локальному отчёту.
- В аналитике не хранятся открытые GUID поставщиков и проекты из выгрузки. Для различения исходных строк используется их хеш. Имена товаров и цены остаются в локальной БД, потому что необходимы каталогу.

Это защита сетевого поведения и файлов проекта. Она не удаляет ранее созданные копии вне проекта и не заменяет разграничение доступа к самому компьютеру и локальной БД.

## История Git

`data/tenders.xlsx` обнаружен уже отслеживаемым и сохранённым в старом коммите. Файл убран из индекса текущих изменений с сохранением на диске. Новый `data/orders.xlsx` игнорируется. Ни одна таблица не должна входить в будущие коммиты обычным `git add`.

Старый коммит с `tenders.xlsx` присутствует также в локальной ссылке на удалённую ветку. Это свидетельство состояния локальной Git-истории, а не проверка текущего содержимого сервера. `.gitignore` и удаление из индекса **не удаляют файл из прошлых коммитов**. История и удалённый репозиторий в этой работе не переписывались; push не выполнялся. До дальнейшей публикации необходимо отдельно согласовать очистку затронутой истории и копий репозитория.

Проверка новых изменений без печати содержимого:

```powershell
git check-ignore data/tenders.xlsx data/orders.xlsx
git ls-files '*.xlsx' '*.xls' '*.xlsm' '*.xlsb'
```

Первая команда должна показать оба файла, вторая — не возвращать конфиденциальных таблиц. Очистку старой истории нельзя заменять этими проверками.
