# Аналитика закупок

Реализация использует существующие React/TypeScript, Fastify, ExcelJS и PostgreSQL. Отдельный раздел не обращается к рекомендациям, не использует embeddings для сопоставления цен и не перезаписывает каталог тендеров.

Блоки загрузки Excel и отчёта импорта удалены со страницы. Локальный CLI и вспомогательные API импорта сохранены; страница не запрашивает отчёт при открытии.

## Устройство

- `backend/src/analytics/import.ts`: чтение небольшого Excel, определение заголовков, проверка чисел и дат, отчёт по строкам.
- `local-file.ts`: адаптер предоставленной большой выгрузки заказов и предложений. Файл читается локально; большие листы обрабатываются потоком.
- `domain.ts`: точная идентичность товара, совместимость условий и процент отклонения.
- `repository.ts`: пакетные вставки, параметризованные SQL-фильтры, пагинация и агрегации.
- `readiness.ts`: агрегированная оценка доступности средней и полного графика без выдачи строк, идентификаторов и цен.
- `routes.ts`: проверка запросов и API.
- `shared/src/analytics.ts`: контракты.
- `frontend/src/analytics/`: загрузка, фильтры, показатели, SVG-график, таблица и состояния сервиса.

Миграция создаёт отдельную `analytics_purchases` и индексы товара, региона/даты, даты и совместимости. Файлы и доступ к существующим тендерам не мигрируются. Импорт проходит одной транзакцией: записи подаются пакетами по 500; ошибка чтения или записи откатывает весь импорт. SHA-256 идентификаторы и `ON CONFLICT DO NOTHING` предотвращают повторную вставку одинаковых строк.

Все запросы одной аналитической выдачи выполняются в `REPEATABLE READ READ ONLY`: таблица, число записей и расчёт используют один снимок БД. `LIMIT/OFFSET` применяется только к таблице. Агрегации выполняются по всей подходящей выборке, включая остальные страницы.

Список товаров в начальных фильтрах ограничен 200 значениями. Отдельный серверный поиск возвращает до 50 подходящих товаров. Полный каталог не загружается в React. Ввод поиска откладывает запрос на 200–250 мс; предыдущие запросы отменяются. Ответ хранится с ключом фильтров: показатели прошлого запроса сразу скрываются при смене условий.

## Контракты API

| Адрес                               | Назначение                                                      |
| ----------------------------------- | --------------------------------------------------------------- |
| `GET /api/analytics/options`        | Число записей, доступные поля и справочники                     |
| `GET /api/analytics/readiness`      | Локальные счётчики пригодности данных для отчёта о внедрении    |
| `GET /api/analytics/products?q=...` | Поиск точного товара для фильтра                                |
| `GET /api/analytics/purchases`      | Страница каталога, выбранная строка, средние и временные группы |
| `POST /api/analytics/import`        | Проверка или добавление небольшого `.xlsx` с выбранного листа   |
| `GET /api/analytics/import-status`  | Локальный отчёт последнего большого импорта                     |

Параметры каталога: `q`, `product`, `region`, `status`, `period=1|3|6|12|all`, `selectedId`, `comparisonRegion`, `page`, `pageSize`. Размер страницы — максимум 100. Дополнительный регион должен отличаться от основного. Без основного региона можно смотреть каталог, но средняя не рассчитывается. Выбор строки автоматически устанавливает её регион, если основной регион ещё не выбран.

## План внедрения

Вкладка «Внедрение» реализована в `frontend/src/report/IntegrationReport.tsx`. В ней остались места подключения, готовность данных, расчёт, правило графика, условный пример и шаги внедрения. Общая справка о компании, публичные источники, сроки и вводные разделы удалены. В шапке оставлены четыре рабочих раздела; бейдж «Прототип» и справочная вкладка «Как это работает» убраны. Постоянные технические сообщения об Excel также скрыты; активная обработка и ошибки продолжают показываться.

Загрузка счётчиков выделена в `ReadinessAssessment.tsx`. План доступен независимо от загрузки основного каталога: сбой API скрывает только счётчики и предлагает повторную попытку.

Оценка средней использует все даты и считает строки, в чьей группе «товар + условия цены + регион» есть хотя бы один другой номер документа. Это доступность расчёта, а не достаточность статистики. Оценка графика использует последние 6 месяцев и основной регион каждой строки, без поиска и дополнительной группы. Нужны все месячные интервалы после исключения всех строк выбранного документа. Если документ является единственным источником хотя бы одного месяца, его строки не считаются пригодными для полного графика. Доля графиков считается от всех строк периода, включая строки с неполными условиями; доля средней — от строк с известными условиями и регионом. Знаменатели явно показаны в интерфейсе.

API возвращает только счётчики, границы периода и время вычисления. Отдельные документы, названия, номера, поставщики и цены не входят в этот ответ. Фиксированные примеры отчёта являются условными, а результаты реального каталога читаются локально при открытии вкладки и не записываются в исходный код.

## Выборки и формулы

Для небольшого общего формата необходимы характеристики плюс точный код/товар либо явно подтверждённая группа сравнения. Для номенклатуры предоставленной выгрузки сравниваются точный код и полное наименование. Обязательны известные и совпадающие единица, валюта, режим НДС и вид цены. Неизвестные условия блокируют сравнение и объясняются пользователю.

Цены заказов и предложений различаются. Источник и статус входят в вид цены; разные состояния документа не объединяются. Из обеих групп исключаются все строки номера выбранной закупки. Поиск, товар, статус и период применяются к обеим группам; основной и дополнительный регионы фильтруются отдельно.

При полном положительном количестве используется `sum(unit_price * quantity) / sum(quantity)`. Иначе используется `avg(unit_price)` по всем корректным ценам; объём возвращается как неизвестный и указывается арифметический метод. Нулевая или отсутствующая средняя не порождает процент. Отклонение: `(selected_price / main_mean - 1) * 100`.

Даты интерпретируются как календарные даты. Отсчёт периода идёт от текущей даты UTC+5. Excel-даты, серийные значения 1900/1904 и строго проверенные строки дат поддерживаются общим адаптером. Последний день месяца при сдвиге периода ограничивается последним существующим днём. Без даты запись доступна только за весь период; в этом режиме она участвует в показателях, но отсутствует на временной оси.

Группировка: дни для короткой малой выборки, недели до 120 дней, затем месяцы. Неделя начинается в понедельник. Первый и последний интервалы ограничиваются точными датами выбранного периода. Каждый пустой интервал содержит `price: null`, а не ноль. Синяя линия показывает основной регион, светло-синяя — явно выбранный дополнительный, зелёная точка — выбранную закупку на её исходной дате. В подсказках указаны интервал, средняя, количество, метод и известный объём.

Полнота проверяется в `frontend/src/analytics/chartState.ts`: нужно не менее двух интервалов, корректная положительная средняя и строки в каждом интервале. У выбранной закупки должны быть дата и единичная цена, а в сравнительной выборке не должно быть строк без даты. Правило применяется к основной и каждой явно включённой дополнительной группе. Если любая проверка не проходит, весь SVG-график, оси и легенда отсутствуют; отдельная зелёная точка не подменяет историю цены. Значения не интерполируются и пропуски не заполняются нулями. Полнота относится только к загруженной истории, а не к рынку в целом.

Вместо неполного графика показываются причина и раскрытый «Разбор выбранной закупки»: её номер, дата и цена, исключение выбранного документа, число сопоставимых строк, число заполненных интервалов и таблица фактических средних с отметками «Нет данных». У полного графика этот разбор доступен в свёрнутом виде. При активном поиске отдельно объясняется его влияние: поиск по одному номеру может исключить все другие документы из сравнительной выборки. Для более широкой истории можно выбрать весь период и использовать фильтр товара вместо точного номера документа.

Контрольный условный пример: выбранный документ — в октябре, другие сопоставимые документы есть только в июле и сентябре. Для периода 25 апреля – 25 октября получается семь месячных интервалов с учётом неполных крайних месяцев. Заполнены два, в остальных пяти данных нет; выбранный октябрьский документ исключён. График скрывается, а разбор показывает оба заполненных интервала и пять пропусков. Этот пример не содержит реальных цен или названий из конфиденциальной выгрузки.

## Исходная выгрузка и ограничения

Проверены листы и заголовки локального `orders.xlsx`; реальные строки и цены в эту документацию не включены. Используются исходные строки заказов и запросов, сводный лист не импортируется. В файле нет самостоятельного поля валюты: KZT подтверждено пользователем и отмечается в происхождении записей. «Цена без НДС» и «Сумма с НДС» сохраняют разные режимы; общая сумма не выдаётся за цену товара.

Строки с отрицательными/нулевыми ценами, неположительным количеством, некорректными датами и формулами в значимых полях пропускаются. Пустое количество остаётся неизвестным. Отчёт содержит исходные номера строк и причины; список замечаний ограничен первыми 100, общий счётчик полный. Совпадающие строки при повторном импорте не обновляют существующие: для изменённого содержимого создаётся новая запись. Версионное замещение и удаление исправленных строк не реализованы.

Это локальный прототип без авторизации и подтверждения исполнения/оплаты документов. Точное совпадение номенклатуры не проверяет неуказанные характеристики. Образец графика не был приложен, поэтому расположение реализовано по текстовому описанию.
