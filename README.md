# Bnect · рекомендации закупок

Локальное приложение на React + TypeScript + Vite, Fastify и PostgreSQL 17 + pgvector. Основной сценарий: **каталог → сведения о тендере → до пяти похожих закупок**. В меню четыре раздела: «Закупки», «Аналитика», «Карта векторов» и «Внедрение». Профиль поставщика для них не требуется.

Похожие закупки строго ограничены регионом выбранного тендера до ранжирования. Для Астаны не возвращаются закупки Атырау и наоборот. Неизвестный регион даёт пустую подборку; если подходящих закупок меньше пяти, другие регионы не добавляются. Правило действует и для рекомендаций карты, и для GET/POST API подбора по тендеру.

Карта показывает 2D PCA-проекцию на Canvas, выбранный тендер и его рекомендации. Доступны категории, перетаскивание, масштаб под курсором, стрелки и +/−. Поиск находит тендер во всём каталоге, включает его категорию и центрирует карту. Фильтры карты не меняют состав рекомендаций.

Подбор использует представление `work-scope-v2`: деятельность и сфера из источника, затем предмет без служебного «Открытый тендер» и явно обозначенного названия объекта/ЖК. Кандидаты ограничиваются той же деятельностью, если она указана; pgvector ранжирует E5 embeddings по косинусному сходству. Повторные смысловые тексты и распознанные объекты, включая очереди, пропускаются. Очистка названий может быть неполной при нестандартных формулировках; рекомендации не проверяют требования допуска.

Excel загружается из **`data/tenders.xlsx`**: первый лист, до 50000 строк, 32 столбцов и 5 МБ. Backend автоматически проверяет появление и изменение файла раз в две секунды, валидирует строки, обновляет записи по номеру и вычисляет embeddings. Повторный запуск не пересчитывает неизменившиеся тексты. Ошибки и завершение видны в журнале backend; после импорта обновите страницу. При ошибке исправьте файл и сохраните заново или перезапустите backend. Заголовки совпадают с CSV ниже; формулы нужно заменить значениями, `.xls` сохранить как `.xlsx`. Кнопка загрузки через интерфейс убрана.

При проверке Docker-запуска 26.10.2026 в локальной БД было 13 007 проиндексированных тендеров из предоставленного `data/tenders.xlsx`, без demo-тендеров. Это снимок состояния, а не требование к новой установке. Второй лист со сводкой и лист удалённых записей не импортируются. Неизвестные регионы сохраняются с `regionId=null`. Реальная БД поставщиков не подключена.

## Запуск

Для запуска нужен только запущенный Docker Desktop (Linux containers). Из корня проекта выполните одну команду:

```powershell
docker compose up --build -d
```

Открыть **http://127.0.0.1:5174**. Docker соберёт frontend и backend, дождётся готовности PostgreSQL, выполнит миграции и запустит API. Устанавливать Node.js, выполнять `npm ci`, копировать `.env` или запускать миграции вручную не требуется. При первой сборке нужен интернет для базовых образов и npm-зависимостей.

Существующая БД сохраняется в прежнем volume `bnect_pgdata`. Excel-файлы из `data/` и модель из `.cache/models/` подключаются только для чтения и не входят в образы. `data/tenders.xlsx` импортируется и индексируется автоматически в фоне; неизменившиеся тексты не пересчитываются. Для рекомендаций нужно завершить индексацию. Существующая аналитика закупок сохраняется; импорт нового `data/orders.xlsx` выполняется отдельно с явным указанием валюты.

Модель работает из локального кеша `.cache/models`; сетевая загрузка отключена. На новом компьютере заранее подготовьте этот кеш: без него каталог работает, а рекомендации возвращают понятную ошибку. Конфиденциальные Excel-файлы в Git не входят и размещаются в `data/` отдельно.

Проверка запуска и журналы:

```powershell
docker compose ps
docker compose logs -f backend
```

Проверка API: http://127.0.0.1:5174/api/health (также доступен напрямую на http://127.0.0.1:3001/api/health). Все порты опубликованы только на `127.0.0.1`. Если порт занят, его можно изменить через `FRONTEND_PORT` или `BACKEND_PORT` в `.env`; внутри контейнеров адреса остаются прежними. `docker compose stop` останавливает проект с сохранением БД; `docker compose down` удаляет контейнеры, сохраняя volume. Повторный запуск — та же команда `docker compose up --build -d`.

Для ручной переиндексации после смены модели или формата текста:

```powershell
docker compose exec backend node backend/dist/backend/src/cli.js reindex
```

Для проверки и импорта аналитики с подтверждённой валютой KZT:

```powershell
docker compose exec backend node backend/dist/backend/src/analytics/import-cli.js data/orders.xlsx --currency KZT --dry-run
docker compose exec backend node backend/dist/backend/src/analytics/import-cli.js data/orders.xlsx --currency KZT
```

### Разработка без контейнеров приложения

Для разработки нужны Node.js 22.17+ с npm и Docker Desktop для PostgreSQL:

```powershell
Copy-Item .env.example .env
npm ci
docker compose up -d db
npm run db:migrate
npm run dev
```

Перед `npm run dev` остановите контейнеры приложения командой `docker compose stop frontend backend`, если они запущены. Открыть **http://127.0.0.1:5174**. Backend: http://127.0.0.1:3001/api/health. Порт frontend зафиксирован; если он занят, Vite сообщает об ошибке вместо незаметной смены адреса. Порт БД — 55432; он отличается от стандартного, чтобы уменьшить вероятность конфликта с существующими проектами.

При старте backend автоматически импортирует и индексирует `data/tenders.xlsx`. После отдельного CSV-импорта выполните `npm run db:index`: неизменившиеся тексты пропускаются. После смены модели, revision, нормализации или формата текста выполните `npm run db:reindex`. Размерность зафиксирована: 384; для другой нужна миграция схемы.

Модель: `Xenova/multilingual-e5-small`, revision `761b726` (полный SHA: `761b726dd34fb83930e26aab4e9ac3899aa1fa78`), Transformers.js `3.8.1`, ONNX `q8`, mean pooling, L2-нормализация. Документы получают префикс `passage:`, запросы поставщика и выбранного тендера — `query:`. Идентификатор, регион, дата, номер и способ закупки не входят в смысловой текст. География и остальные включённые ограничения применяются структурированными SQL-фильтрами.

Демонстрационное время **23.10.2026, 14:00 (UTC+5)** / `2026-10-23T09:00:00.000Z` фиксировано и видно в интерфейсе. Оно используется для воспроизводимой проверки синтетических дедлайнов, а не выдаётся за текущее время. Дата создания не является дедлайном. При неизвестных статусе/сроке показывается «Доступность участия неизвестна».

```powershell
npm run typecheck
npm test
npm run test:analytics
npm run build
npm run format:check
# После миграций и индексации каталога; использует настоящие БД и модель:
npm run test:integration
```

Команды проверок выполняются в локальном окружении Node.js после `npm ci`. Unit-тесты не скачивают модель. Интеграционные проверки аналитики используют временную схему PostgreSQL; проверки рекомендаций требуют проиндексированный каталог и кеш модели. Исторические результаты: [рекомендации](docs/verification.md), [аналитика](docs/purchase-analytics-verification.md). Они не заменяют запуск проверок для текущих изменений или нагрузочное тестирование.

## Аналитика закупок

Вкладка «Внедрение» содержит практический план: места включения средней цены и графика, готовность данных, расчёт, пример и шаги подключения. Общая справка о компании, публичные источники и вводные разделы удалены. Счётчики готовности вычисляются локально; реальные цены и документы не записываются в исходный код плана.

Вкладка «Аналитика» содержит поиск по номеру, названию и коду, фильтры товара, региона, статуса и периода, таблицу с серверной пагинацией, ценовую карточку и график. По умолчанию показаны последние 6 месяцев от текущей даты UTC+5; доступны 1, 3, 6, 12 месяцев и весь период. При отсутствии дат используется весь период, а график объясняет ограничение.

Данные хранятся отдельно в `analytics_purchases`; импорт не меняет `tenders` и embeddings. Excel и отчёт импорта не загружаются через страницу. Вспомогательный API принимает `.xlsx` до 5 МБ, потоковый CLI — локальную выгрузку до 100 МБ / 1 млн строк. Повтор того же содержимого, включая переименованный файл, не создаёт новые записи.

Docker-команды импорта приведены в разделе запуска. Для разработки через Node.js в PowerShell используйте `npm.cmd`, чтобы аргументы передавались без изменений:

```powershell
npm run db:migrate
# Проверить без изменения каталога:
npm.cmd run analytics:import -- data/orders.xlsx --currency KZT --dry-run
# Добавить проверенные строки в отдельный каталог:
npm.cmd run analytics:import -- data/orders.xlsx --currency KZT
```

`--currency` задаётся только после подтверждения владельцем данных. Для текущей выгрузки пользователь подтвердил **KZT**; столбца валюты в ней нет. Импортируются строки заказов и предложений по запросам, сводный и служебный листы пропускаются. Запрошенное количество не подменяет предложенное. Для сравнения берётся явно указанная **цена без НДС**; сумма с НДС сохраняется с отдельной подписью и не используется для её восстановления. Цены заказов и предложений разделяются по источнику и статусу. Статус заказа сам по себе не считается доказательством оплаты или фактического исполнения.

Сопоставимость в этой выгрузке требует точного совпадения кода и полного наименования номенклатуры, единицы, валюты, режима НДС и вида цены. Для общего формата нужны код/товар вместе с характеристиками либо явно подтверждённая группа сравнения. Категория и близость названия не используются как доказательство. Из расчёта исключаются все строки выбранного номера документа. Основной регион ограничивает выборку до агрегации; другой регион появляется только по явному выбору пользователя.

Средняя использует все подходящие строки независимо от страницы таблицы: при полном количестве — Σ(цена × количество) / Σ(количество), иначе — среднее арифметическое с отметкой о неполном количестве. График показывается только для полного ряда: не менее двух интервалов и корректная средняя в каждом интервале выбранного периода для обеих включённых групп. Одиночные точки, пропуски и строки без дат в сравнительной выборке скрывают весь график вместе с осями и легендой. Вместо него показываются причина и разбор выбранной закупки с числом строк и таблицей интервалов. Подсказка полного графика содержит период, цену, число записей и известный объём. Результат называется «средняя цена по данным Excel» и не подтверждает среднерыночную цену.

Результат большого импорта и первые 100 замечаний сохраняются в `output/analytics/import-report.json` при запуске через Node.js, а в Docker — в `/app/output/analytics/import-report.json` на постоянном volume `bnect_reports`. Страница не запрашивает этот отчёт. После импорта обновите вкладку аналитики. Исходные строки, цены и контрагенты в консоль не выводятся; GUID поставщиков и проекты заменяются непрозрачным ключом для исключения повторов. Исходный файл на диске сохраняется.

Подробнее: [расчёты и API](docs/purchase-analytics.md), [локальная обработка и границы защиты](docs/privacy.md).

## Импорт CSV

Пример находится в `data/tenders.example.csv`. Нужны UTF-8 и заголовки:

```text
№ тендера;Наименование тендера;Регион;Дата создания;Сфера (группа);Сфера деятельности;Способ закупки;Вид закупки
```

```powershell
docker compose exec backend node backend/dist/backend/src/cli.js import data/tenders.example.csv --dry-run
docker compose exec backend node backend/dist/backend/src/cli.js import data/tenders.example.csv
docker compose exec backend node backend/dist/backend/src/cli.js index
```

Локальные эквиваленты: `npm run db:import -- путь.csv [--dry-run]` и `npm run db:index`. Dry-run валидирует данные и не изменяет БД. Записи обновляются по уникальному `externalNumber`. Ошибки сообщаются с номерами строк; политика дублей описана в [архитектуре](docs/architecture.md). Отсутствующие статусы и сроки не выдумываются. Неизвестный регион получает `null`; «Астана», «г. Астана» и «Нур-Султан» нормализуются в один ID, Алматы и Алматинская область различаются.

## Структура и перенос

```text
frontend/src/      React: каталог, сведения, карта, аналитика, план внедрения
frontend/src/hooks/  загрузка каталога и опрос состояния импорта
backend/src/       Fastify, сервис рекомендаций, pgvector, embedding provider, PCA
backend/src/routes/  HTTP-маршруты и валидация запросов
backend/src/tenders/  типы БД, импорт и индексация тендеров
backend/src/data/  регионы, CSV/XLSX-адаптеры и синтетические тестовые данные
backend/src/analytics/  импорт закупок, SQL-выборки, расчёты и API аналитики
backend/tests/     unit- и интеграционные проверки
shared/src/        TypeScript-контракты API
data/              локальные Excel и вымышленный пример CSV
docker/            nginx для production frontend и проксирования API
docs/              алгоритмы, API, ограничения и история проверок
Dockerfile         сборка frontend и backend
compose.yaml       frontend, backend, PostgreSQL и постоянные volumes
```

Подробнее: [алгоритм, реальный SQL, PCA и масштабирование](docs/architecture.md). Существующий большой проект может вызывать сервис рекомендаций через HTTP либо перенести сервис, интерфейсы адаптеров и миграции. Нет Redis, очередей, отдельных AI-сервисов и скрытых правил ранжирования.

Приложение предназначено для локальной работы и не содержит авторизации. Рекомендации учитывают специализацию и географию; лицензии, квалификация и остальные условия допуска не проверяются. Косинусное сходство не является вероятностью победы или подтверждённым допуском.

Совместимость сверена по первичным источникам: [ONNX-модель и Transformers.js](https://huggingface.co/Xenova/multilingual-e5-small), [исходная модель E5](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/README.md), [API Transformers.js 3.8.1](https://huggingface.co/docs/transformers.js/v3.8.1/api/pipelines), [точный и approximate-поиск pgvector](https://github.com/pgvector/pgvector).
