# Bnect · рекомендации закупок

Локальный технический прототип: React + TypeScript + Vite, Fastify, PostgreSQL 17 + pgvector. Интерфейс максимально простой: **список тендеров → сведения о выбранном тендере → до пяти похожих закупок**. Похожие закупки появляются автоматически. Рейтинг вычисляется настоящей embedding-моделью, хранение и точный косинусный поиск выполняются PostgreSQL.

Основной сценарий остаётся простым: каталог → сведения → пять похожих. Возвращены вкладки «Векторное пространство» (интерактивная 2D PCA-карта, масштаб, выбранный тендер и его top-5) и «Как это работает». Профиль поставщика для этих сценариев не требуется.

Карта рисуется на Canvas: обычные точки радиусом 1,7 px, категории включаются отдельно. Доступны перетаскивание, масштаб под курсором, управление стрелками и +/−. Поиск во всём каталоге находит точку, включает её категорию и центрирует её на карте. «Показать выбранные» возвращает видимые категории в кадр. Фильтры карты не меняют состав рекомендаций.

Подбор похожих использует представление `work-scope-v2`: вначале идут деятельность и сфера из источника, затем предмет без служебного «Открытый тендер» и явно обозначенного названия объекта/ЖК. Кандидаты ограничиваются той же деятельностью, если она указана; внутри этой группы pgvector ранжирует реальные E5 embeddings. Повторные смысловые тексты и распознанные объекты (включая явно указанные очереди) пропускаются. При нехватке разных подходящих закупок выдача может быть короче пяти. Это не гарантирует проверку требований, а очистка названий объектов может быть неполной при нестандартных формулировках. Изменение формата потребовало явной переиндексации всех 13 007 документов; исходные названия в БД сохранены.

Excel загружается из **`data/tenders.xlsx`**: первый лист, до 50000 строк, 32 столбцов и 5 МБ. Backend автоматически проверяет появление и изменение файла раз в две секунды, валидирует строки, обновляет записи по номеру и вычисляет embeddings. Повторный запуск не пересчитывает неизменившиеся тексты. Ошибки и завершение видны в журнале backend; после импорта обновите страницу. При ошибке исправьте файл и сохраните заново или перезапустите backend. Заголовки совпадают с CSV ниже; формулы нужно заменить значениями, `.xls` сохранить как `.xlsx`. Кнопка загрузки через интерфейс убрана.

Рабочий каталог загружен из предоставленного `data/tenders.xlsx`: 13 008 строк, 13 007 уникальных номеров (для одного повторяющегося номера использована последняя корректная строка). Все 96 демонстрационных тендеров удалены. Все 13 007 записей проиндексированы настоящей моделью. Второй лист со сводкой и лист удалённых записей не импортируются. Неизвестные справочнику регионы сохраняются с `regionId=null` и видны в режиме всех регионов. Реальная БД поставщиков не подключена.

## Запуск

Нужны Node.js 22.17+ с npm и запущенный Docker Desktop (Linux containers). Команды выполняются из корня проекта. Первый запуск модели требует доступа к Hugging Face и загрузки ONNX-весов; далее используется локальный кеш `.cache/models`.

```powershell
Copy-Item .env.example .env
npm ci
docker compose up -d db
npm run db:migrate
npm run db:index
npm run dev
```

Открыть **http://127.0.0.1:5174**. Backend: http://127.0.0.1:3001/api/health. Порт frontend зафиксирован; если он занят, Vite сообщает об ошибке вместо незаметной смены адреса. Порт БД — 55432; он отличается от стандартного, чтобы уменьшить вероятность конфликта с существующими проектами. Compose создаёт отдельный постоянный volume. `docker compose stop` останавливает БД, сохраняя данные.

Индексация выполняется отдельной командой: API может показывать список закупок до её завершения, но для рекомендаций нужны embeddings. Повторный `db:index` пропускает записи с неизменившимся смысловым текстом. После изменения модели, её revision, способа нормализации или формата текста требуется явный `npm run db:reindex`. Размерность этого прототипа зафиксирована: 384. Для другой размерности нужна отдельная миграция схемы.

Модель: `Xenova/multilingual-e5-small`, revision `761b726` (полный SHA: `761b726dd34fb83930e26aab4e9ac3899aa1fa78`), Transformers.js `3.8.1`, ONNX `q8`, mean pooling, L2-нормализация. Документы получают префикс `passage:`, запросы поставщика и выбранного тендера — `query:`. Идентификатор, регион, дата, номер и способ закупки не входят в смысловой текст. География и остальные включённые ограничения применяются структурированными SQL-фильтрами.

Демонстрационное время **23.10.2026, 14:00 (UTC+5)** / `2026-10-23T09:00:00.000Z` фиксировано и видно в интерфейсе. Оно используется для воспроизводимой проверки синтетических дедлайнов, а не выдаётся за текущее время. Дата создания не является дедлайном. При неизвестных статусе/сроке показывается «Доступность участия неизвестна».

## Проверки

```powershell
npm run typecheck
npm test
npm run build
# После migrate, seed и index; использует настоящие БД и модель:
npm run test:integration
```

Unit-тесты не скачивают модель. Интеграционные проверки требуют готовую локальную БД и кеш модели; они не заменяют проверку производительности на реальном объёме. Прототип не содержит авторизации и предназначен для локальной демонстрации.

## Импорт CSV

Пример находится в `data/tenders.example.csv`. Нужны UTF-8 и заголовки:

```text
№ тендера;Наименование тендера;Регион;Дата создания;Сфера (группа);Сфера деятельности;Способ закупки;Вид закупки
```

```powershell
npm run db:import -- data/tenders.example.csv --dry-run
npm run db:import -- data/tenders.example.csv
npm run db:index
```

Dry-run валидирует данные и не изменяет БД. Записи обновляются по уникальному `externalNumber`. Ошибки сообщаются с номерами строк; поведение при ошибках и дублях описано в [архитектуре](docs/architecture.md). Импорт не выдумывает отсутствующие статусы и сроки. Неизвестный регион получает `null`: виден в режиме «Все регионы» и исключён при региональном ограничении. «Астана», «г. Астана» и «Нур-Султан» нормализуются в один ID; Алматы и Алматинская область различаются.

## Структура и перенос

```text
frontend/          React, каталог, сведения о тендере и похожие закупки
backend/src/       Fastify, сервис рекомендаций, pgvector, embedding provider, PCA
backend/src/data/  воспроизводимые demo-данные, регионы, CSV-адаптер
backend/tests/     unit- и интеграционные проверки
shared/src/        TypeScript-контракты API
data/              пример CSV
docs/              SQL, устройство алгоритма и границы интеграции
compose.yaml       только PostgreSQL с pgvector
```

Подробнее: [алгоритм, реальный SQL, PCA и масштабирование](docs/architecture.md). Существующий большой проект может вызывать сервис рекомендаций через HTTP либо перенести сервис, интерфейсы адаптеров и миграции. Нет Redis, очередей, отдельных AI-сервисов и скрытых правил ранжирования.

Ограничения: рекомендации учитывают специализацию и географию. Лицензии, квалификация и остальные условия допуска не проверяются. Косинусное сходство не является вероятностью победы или подтверждённым допуском.

Совместимость сверена по первичным источникам: [ONNX-модель и Transformers.js](https://huggingface.co/Xenova/multilingual-e5-small), [исходная модель E5](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/README.md), [API Transformers.js 3.8.1](https://huggingface.co/docs/transformers.js/v3.8.1/api/pipelines), [точный и approximate-поиск pgvector](https://github.com/pgvector/pgvector).
